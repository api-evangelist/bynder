## API Reference
- [Authorize endpoint](https://api.bynder.com/reference/get_v6-authentication-oauth2-auth.md): When using the Authorization Code grant, redirect the user to the Authorize application endpoint. After the user is authenticated and approves the authorization request, Bynder will redirect the user back with an authorization code which can then be passed to the Token endpoint.
- [Using an authorization code](https://api.bynder.com/reference/post_v6-authentication-oauth2-token-authorization.md): Use the token endpoint to retrieve an access token which can be used to authorize API requests. This endpoint supports the Authorization Code grant, the Refresh Token grant and the Client Credentials grant.
- [Using a refresh token](https://api.bynder.com/reference/post_v6-authentication-oauth2-token-refresh.md): Use the token endpoint to retrieve an access token which can be used to authorize API requests. This endpoint supports the Authorization Code grant, the Refresh Token grant and the Client Credentials grant.
- [Using client credentials](https://api.bynder.com/reference/post_v6-authentication-oauth2-token-client-credentials.md): Use the token endpoint to retrieve an access token which can be used to authorize API requests. This endpoint supports the Authorization Code grant, the Refresh Token grant and the Client Credentials grant.
- [Retrieve scopes](https://api.bynder.com/reference/get_v6-authentication-oauth2-scopes.md): Retrieve a JSON formatted overview of the existing scopes within Bynder and the required user permissions.
- [Retrieve security profiles](https://api.bynder.com/reference/get_api-v4-profiles.md): To determine the security profile for your user you can compare the security profile id with the profileId retrieved from either the Retrieve specific user or Retrieve current user call. It’s the API’s responsibility to enforce that users can only perform allowed actions but nevertheless we recommend that your application checks whether or not an action can be performed because this will create a better user experience.
- [Retrieve specific security profile](https://api.bynder.com/reference/get_api-v4-profiles-id.md): This call allows you to retrieve your own security profile without requiring the PERMISSIONMANAGEMENT security role. In order to get your own security profile use your user profile id retrieved by executing the Specific User or Current User call.
- [Retrieve users](https://api.bynder.com/reference/get_api-v4-users.md)
- [Create user](https://api.bynder.com/reference/post_api-v4-users.md)
- [Retrieve specific user](https://api.bynder.com/reference/get_api-v4-users-id.md)
- [Modify user](https://api.bynder.com/reference/post_api-v4-users-id.md)
- [Delete user](https://api.bynder.com/reference/delete_api-v4-users-id.md)
- [Retrieve current user](https://api.bynder.com/reference/get_api-v4-currentuser.md): Retrieve the current user information. Unlike [Retrieve specific user](#reference/users/specific-user-operations/retrieve-specific-user) this call doesn't require you to know your user id in order to retrieve your current user information.
- [Retrieve account information](https://api.bynder.com/reference/get_api-v4-account.md)
- [Retrieve derivatives](https://api.bynder.com/reference/get_api-v4-account-derivatives.md): A derivative is a file that is based on another source, for example, a low-resolution representation of a print-quality photo. During the upload process, Bynder can automatically create pre-defined image derivatives with different dimensions, quality, and format. Bynder can either maintain the original aspect ratio of an image, or crop or pad an image to fit the specified dimensions. We can create smaller versions of your original image asset in both a JPG and PNG file extension. However, the resolution of derivatives can't be larger than the original file.
- [List groups](https://api.bynder.com/reference/listgroups.md): Returns a paginated list of groups with member count.  Requires the **GROUPMANAGEMENT** security role.
- [Create a group](https://api.bynder.com/reference/creategroup.md): Creates a new group.  Requires the **GROUPMANAGEMENT** security role.
- [Get group by ID](https://api.bynder.com/reference/getgroup.md): Returns a single group by its ID, including member count.  Requires the **GROUPMANAGEMENT** security role.
- [Update a group](https://api.bynder.com/reference/updategroup.md): Updates the name and/or description of an existing group.  At least one field must be provided. Only the fields included in the request body are updated (partial update semantics).  Requires the **GROUPMANAGEMENT** security role.
- [Delete a group](https://api.bynder.com/reference/deletegroup.md): Deletes a group and removes all its members from it.  Requires the **GROUPMANAGEMENT** security role.
- [Add users to a group](https://api.bynder.com/reference/adduserstogroup.md): Adds one or more users to the specified group. Pass a single-element array to add one user.  Users that are already members of the group are silently ignored (the operation is idempotent). An empty `user_ids` array is accepted and is a no-op.  Requires the **GROUPMANAGEMENT** security role.
- [Remove users from a group](https://api.bynder.com/reference/removeusersfromgroup.md): Removes one or more users from the specified group. Pass a single-element array to remove one user.  Users not currently in the group are silently ignored (the operation is idempotent). An empty `user_ids` array is accepted and is a no-op.  Requires the **GROUPMANAGEMENT** security role.
- [Retrieve groups](https://api.bynder.com/reference/retrievegroupslegacy.md): Requires the **GROUPMANAGEMENT** security role.
- [Retrieve asset usage](https://api.bynder.com/reference/get_api-media-usage.md): Retrieve asset usage information.
- [Create asset usage](https://api.bynder.com/reference/post_api-media-usage.md): Create a new asset usage entry.
- [Delete asset usage](https://api.bynder.com/reference/delete_api-media-usage.md): Delete an asset usage entry.
- [Sync asset usage](https://api.bynder.com/reference/post_api-media-usage-sync.md): Sync all usage from a single integration.
- [Retrieve assets](https://api.bynder.com/reference/get_api-v4-media.md): `original` is only returned for assets marked as public and requires the account to have the `seoBaseUrl` setting configured.
- [Retrieve specific asset](https://api.bynder.com/reference/get_api-v4-media-id.md): Requires the **STATISTICS** security role in order to retrieve *views* and *downloads* statistics data in the response, using the `stats` parameter.
- [Modify asset](https://api.bynder.com/reference/post_api-v4-media-id.md): Requires the **MEDIAEDIT** security role. Requires the **MARKPUBLIC** security role in order to change an asset's isPublic state.  **Custom thumbnails**  To set a custom thumbnail, first upload the thumbnail image using the [Modern Stack File Upload](https://api.bynder.com/reference/modern-stack-file-upload) flow, then call this endpoint with the returned file id as `customThumbnailFileId`. To remove an existing custom thumbnail and revert to the automatically generated one, call this endpoint with `removeCustomThumbnail=true`. The two fields are mutually exclusive.
- [Delete asset](https://api.bynder.com/reference/delete_api-v4-media-id.md): Requires the **MEDIAREMOVE** security role.
- [Add metaproperty options](https://api.bynder.com/reference/post_api-media-options.md): These calls allow you to change the metaproperty options attached to an asset.
- [Delete metaproperty options](https://api.bynder.com/reference/delete_api-media-options.md)

The response headers - in particular the `Location` header - are required for the next call, **Upload file chunks**.  > The `{uploadUrl}` path parameter is a placeholder for the signed URL from the previous step.
